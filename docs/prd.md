## 1. 项目概述

### 1.1 一句话

一套运行在家庭 NAS 上的食材库存管理系统，覆盖食材档案、采购入库、批次库存、消耗出库、成本核算、营养估算、临期提醒、采购清单与菜谱关联；通过网页与原生 App 访问，数据完全自有。

### 1.2 解决的五个问题

| # | 问题 | 本项目的回应 |
| --- | --- | --- |
| 1 | 食材分散存放，掌握不了当前库存、重量与到期时间 | 批次化库存 + 位置维度 + 临期提醒 |
| 2 | 多次采购同一食材，批次/价格/保质期不同，算不清成本 | 每批独立成本 + FEFO 分摊 + 尾差结清 |
| 3 | 消耗没记录，估不出支出、趋势与营养摄入 | 流水驱动 + 双口径统计 + 营养快照 |
| 4 | 采购易重复或遗漏，缺少基于最低库存与菜谱的建议 | 低库存阈值 + 菜谱缺口 → 采购清单 |
| 5 | 手工录商品信息成本高 | 条码 + 图片 AI 识别（P2，结果仅作草稿） |

### 1.3 产品目标

- 建立**可信**的家庭食材台账：任何库存变化都可追溯到具体批次与操作设备。
- 支持按**批次**管理保质期、储存位置、采购成本与剩余库存。
- 以**消耗量**为基础估算热量、蛋白质、脂肪、碳水、膳食纤维、钠。
- 通过临期提醒、采购建议、菜谱关联降低浪费与重复采购。
- 数据全部由用户掌控：可导出、备份、恢复，不依赖任何第三方服务。

## 3. 核心业务流程

### 3.1 主流程

```
食材档案 → 采购入库 → 生成独立批次 → 消耗/报损/调整 → 库存流水 → 成本与营养统计
```

### 3.2 扩展流程

```
最低库存 / 菜谱需求 → 计算缺口 → 生成采购清单
批次到期日 → 临期任务 → 页面提醒 + App 本地通知
```

### 3.3 八条核心设计原则（不可违反）

1. **档案与批次分离**：档案描述"是什么"，批次描述"哪一次买的、还剩多少、何时到期"。
2. **每次采购生成独立批次**，不覆盖历史批次。
3. **库存变化必须生成流水**，禁止把"直接改库存余额"当作常规操作。
4. **历史不可物理删除**；撤销通过反向流水实现。
5. **页面展示的余额以服务端计算结果为准**，批次余额字段只是可重算缓存。
6. **数量与重量分别记录**；只有存在明确换算比例时才允许联动。
7. **营养数据在消耗时快照**，后续修改营养档案不得改变历史统计。
8. **默认 FEFO 分配**（先到期先出），用户可手动指定批次但不得突破可用量。

## 4. 功能需求

### 4.1 页面结构

| 导航 | 主要内容 |
| --- | --- |
| 首页 | 库存总价值、周期采购/消耗金额、消耗比例、最近入库、营养摄入、临期提醒 |
| 库存 | 食材列表、批次详情、分类/临期/过期/位置筛选、盘点、调整、报损 |
| 统计 | 采购与消耗趋势、分类金额、库存价值、消耗排行、营养摄入 |
| 记录 | 全部流水：入库、消耗、调整、报损、撤销 |
| 设置 | 已授权设备、分类、单位、储存位置、营养目标、提醒、导出备份、主题 |

> V1.0 实现首页、库存、记录、设置四页 + 配对页；统计页在 V1.1 补齐图表。

### 4.2 首页

- 库存总价值、所选周期采购金额、消耗金额与消耗比例；支持日/周/月/年/自定义范围。
- 最近 4 条入库记录与待处理临期提醒。
- 营养卡片：今日、近三天、本周的热量、蛋白质、脂肪、碳水、膳食纤维、钠。
- **必须标注"按库存消耗量估算"**，避免被误认为实际入口记录。

### 4.3 食材档案与录入

| 字段组 | 字段 |
| --- | --- |
| 基础信息 | 食材名称、图片、分类、品牌、规格、条码、备注 |
| 默认计量 | 数量单位、重量/体积单位、默认单位重量、是否启用双计量 |
| 营养信息 | 营养项目、数值、基准重量/体积、数据来源 |
| 库存策略 | 最低库存数量、最低库存重量、默认储存位置 |
| 识别辅助 | 拍照/相册上传、条码查询、包装信息与营养表 AI 识别（P2） |

**规则**：AI 识别结果只能作为待确认草稿；名称、营养值、生产日期、保质期均须用户确认后才写入档案或批次。

### 4.4 采购入库与批次

- 每次采购生成一个批次，记录购买日期、生产日期、到期日期、开封日期、储存位置。
- 记录采购数量、采购重量、采购总价，并按可用计量方式计算批次成本。
- 同一食材可存在多个批次，各批次保留独立成本与到期日。
- 批次详情展示初始/剩余的数量、重量与成本，以及状态。

### 4.5 消耗出库

- 支持中文模糊搜索、拼音全拼与首字母检索。
- 支持按数量或重量消耗，支持单次与批量消耗。
- 默认 FEFO：有到期日按到期日升序；无到期日排最后；同到期日按入库时间。
- 允许手动选择批次，但不得突破批次可用库存。
- **默认禁止负库存**；批量消耗必须整体成功或整体失败。

### 4.6 库存与记录

- 库存列表支持按分类、临期、过期、无库存、储存位置筛选；按名称、价格、重量、到期日、最近入库排序。
- 食材详情展示全部批次、库存成本、营养档案与历史流水。
- 盘点差异通过 `adjustment` 流水记录；报损通过 `spoilage` 流水记录。
- 撤销消耗通过反向流水恢复库存，**不删除原消耗记录**。

### 4.7 统计与营养

- 财务：采购金额、消耗成本、库存价值、报损金额、分类金额、时间趋势。
- 库存分析：当前数量/重量/价值、消耗排行、采购频率、周转情况。
- 营养：热量、蛋白质、脂肪、碳水、膳食纤维、钠，可配置目标。
- **无消耗记录的日期与"记录为 0"必须区分**，不得把空白天当 0 摄入。
- 统计口径基于系统记录的库存消耗量，不代表全部由本人食用。

### 4.8 临期提醒

- 默认档位：到期前 7 天、3 天、1 天，以及已过期。
- 按**批次**提醒；已无库存的批次不提醒。
- 首页显示提醒条；系统通知由 App 本地通知承载（不依赖推送证书）。
- 开封后保质期（P1）：`opened_date + 开封后保质期` 可覆盖原到期日。

### 4.9 采购清单与菜谱

- 食材可设最低库存；低于阈值生成补货建议。
- 菜谱含名称、图片、分类、份数、制作时间、步骤、所需食材的数量/重量。
- 菜谱可计算库存可满足量与缺少量，并生成采购清单。
- 多个菜谱合并时，相同食材**先合并需求再扣除现有库存**。
- **V1.2 菜谱只用于库存匹配与采购建议，不自动扣库存**。

## 5. 关键业务规则

### 5.1 库存余额

```
库存余额 = 初始库存 + 所有有效流水变化之和
```
批次表的 `remaining_*` 是缓存字段，必须可由 `transaction_allocations` 聚合重算（每日对账）。

### 5.2 成本核算

- 每批次独立核算；单位成本 = `批次剩余成本 ÷ 批次剩余重量（或数量）`。
- 消耗成本 = 本次消耗重量 × 对应批次单位成本；仅按数量管理的食材按数量核算。
- **最后一次消耗结清尾差**：本次把该批次扣完时，成本直接取剩余成本，避免归零后残留分币。
- 多批次消耗成本 = 各批次分摊成本之和，且必须等于单据级成本。

### 5.3 数量与重量

两个独立计量维度。例如"2 包"与"500 克"可同时记录，但**只有用户明确设置"每包 250 克"后才自动同步**；
未设置换算关系却要求换算 → 直接拒绝（`UNIT_NOT_CONVERTIBLE`）。

### 5.4 营养计算与快照

```
营养摄入 = 消耗重量 × 每基准单位营养值 ÷ 营养基准重量
```
每次消耗将结果写入 `consumption_nutrition` 快照表，历史统计只读快照。

### 5.5 并发与事务

- 消耗时对相关批次加行级锁（`SELECT … FOR UPDATE`），避免并发扣减超卖。
- 批量消耗在单一事务内完成：校验 → FEFO 分配 → 计算成本 → 写流水 → 写分配 → 更新批次缓存 → 写消耗单 → 写营养快照。
- 任一步失败全部回滚。
- 写操作支持 `Idempotency-Key`，避免网络重试造成重复入库/消耗。

## 6. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 安全 | 仅局域网/组网可达（`ALLOW_CIDR`）；设备令牌只存哈希；Web 用 HttpOnly Cookie，App 用 Keychain/Keystore |
| 网络 | 不开放公网端口；不做 PWA 安装与系统通知（需 HTTPS） |
| 备份 | 每日 `pg_dump` + 文件目录备份，保留 14 份；每季度演练一次恢复 |
| 性能 | 单用户规模：食材百级、批次千级、流水万级；列表接口 P95 < 300 ms |
| 兼容 | Web：Safari 16+ / Chrome 110+；App：iOS 16+ / Android 10+ |
| 时区 | 数据库存 UTC，业务日期按 `Asia/Shanghai` 计算 |
| 可维护 | 单容器 + 单数据库；`docker compose up -d` 一条命令启动 |

## 7. 验收标准

### 7.1 必须全绿的 9 条（数字不可改）

| 场景 | 输入 | 预期 |
| --- | --- | --- |
| 批次成本 | 批次1 500g/18 元；批次2 1000g/35 元；消耗 300g | FEFO 扣批次1；剩 200g 与 1000g；成本 **10.80**；剩余库存成本 **42.20** |
| FEFO | A 500g 到期 11-10；B 1000g 到期 11-20；消耗 600g | A 清零，B 剩 900g |
| 营养快照 | 每 100g：165kcal / 蛋白 31g / 脂肪 3.6g；消耗 200g | 记录 330kcal / 62g / 7.2g；后续改档案不变 |
| 库存不足 | 请求量 > 可用量 | 拒绝，不产生任何部分流水 |
| 重复请求 | 同 Idempotency-Key 重复提交 | 只产生一笔有效消耗 |
| 并发消耗 | 两请求同时扣同一批次 | 不出现负库存或重复扣减 |
| 撤销消耗 | 撤销已完成消耗 | 新增反向流水、恢复批次库存、原记录保留 |
| 单位不匹配 | 无换算关系却要求自动换算 | 拒绝并提示补充换算关系 |
| 批量回滚 | 批量消耗中一项库存不足 | 整批失败，所有库存保持原值 |

### 7.2 其他必须覆盖

- 临期 7/3/1 天与过期提醒边界；空库存不提醒。
- 批次无到期日期时的 FEFO 排序（排最后，同日期按入库时间）。
- 盘点增加、盘点减少、报损的成本核算。
- 批次剩余归零时成本尾差结清。
- 营养基准单位不同（g / ml / 份）时的换算校验。
- 图片上传非法格式、超大文件、重复文件（checksum 去重）。
- 数据库与文件备份、完整恢复。
- 时区切换后日期展示与统计边界正确。

## 8. 已决策事项（原"待明确"清单的结论）

| 原待明确项 | 结论 | 理由 |
| --- | --- | --- |
| 是否支持 ml/L 与 g/kg 的体积-重量密度换算 | **不做** | 密度因食材而异，无法自动推断；需要时由用户配 `default_unit_weight` 走数量↔重量 |
| 营养数据来源优先级 | **仅手动录入**（P2 加包装表识别，结果需人工确认） | 第三方食品库数据质量不可控 |
| AI 识别用云端还是本地模型 | P2 再定；先只做"图片上传 + 人工填写" | 云端有隐私与成本问题，本地模型对 NAS 硬件要求高 |
| 是否多币种 | **单一货币（人民币）** | PRD 已建议 V1 单币种 |
| 是否多时区 | 数据库 UTC，界面按 `Asia/Shanghai` | 单用户单地 |
| 备份策略 | 每日 pg_dump + 文件 tar，保留 14 份，季度演练 | 家庭规模足够 |

### 本项目新增的决策（原稿未覆盖）

| 项 | 决策 |
| --- | --- |
| 认证方式 | **配对码 → 长期设备令牌**，不做密码（详见 `final-plan.md` §2） |
| 提醒载体 | App 本地通知；不做 PWA 系统通知 |
| 容器数量 | 2 个（api + db），前端由 api 托管 |
| 数值传输 | 金额/重量/营养一律**字符串**，避免前端浮点误差 |

## 9. 术语表

| 术语 | 含义 |
| --- | --- |
| 档案（ingredient） | 食材的"是什么"：名称、分类、营养、默认单位 |
| 批次（batch） | 某一次采购的库存实体：数量、重量、成本、到期日 |
| 流水（transaction） | 一次库存变化的记录，唯一真相 |
| 分配（allocation） | 一笔流水对某个批次的作用量 |
| FEFO | First Expired First Out，先到期先出 |
| 尾差 | 批次扣完时按单位成本算出的微小残值，必须结清为 0 |
| 双计量 | 数量与重量两个独立维度 |
| 营养快照 | 消耗发生时冻结的营养数值，不随档案变化 |
